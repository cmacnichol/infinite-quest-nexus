# Unified character editor and starting cast spec review

**Recommendation.** Revise the design before implementing campaign authority in phase 3. The editor extraction can proceed once the Organize save contract is corrected. The phase 5 evidence rules and phase 6 lifecycle decisions can be settled in their respective releases.

Three independent reviewers covered the opening decisions, domain and context, the editor, API and both clients, and automation and lifecycle. Each cross-checked the corresponding phases, tests and follow-ups. The review used the November 8 spec and repository HEAD `0b1891c9`. Only recovery tests changed since the spec's baseline `87ab54ca`. Line references below refer to the [reviewed spec](../superpowers/specs/2026-11-08-unified-character-editor-and-starting-cast-design.md).

## Campaign authority, discovery and narrator context

1. **Applying a world profile can hide a hand edit.** Lines 245, 294 and 347 disagree for a manual character with a hand-entered role and a blank role in the world. Apply clears overrides on fields that become fixed. The seeded resolver then ignores the remaining stable override, and the old edit route rejects changes to it. Define Apply as a field-by-field transition. Carry a hand value into the campaign profile when the world field is blank, show displaced values when both are populated, and preserve updating-field overrides. Specify what survives detach and reapplication. Test the same hand-entered role against blank and populated world roles. [Current override projection](../../packages/domain/src/campaign-cast.ts#L67)

2. **Reset can restore the wrong identity.** Lines 225, 245, 320 and 501 use the cast record's original `create` for Reset. An existing record can have a different name or alias list, and a first-appearance create can include a narrated alias absent from the roster. Store the source roster name and eligible roster aliases on the active seed. Use those values for Reset, and specify which existing campaign aliases Apply keeps. Test a manual record, a first-appearance alias, migration and an archive round trip. [Identity command](../../packages/contracts/src/campaign-cast.ts#L75)

3. **Long authored values cannot round-trip through the cast API as specified.** Lines 287, 348, 496 and 504 promise full effective values, including 20,000-character goals. A valid 3,000-character background already exceeds the 2,000-character limit on the existing cast profile used by reads, receipts and snapshots. Define separate limits for full detail, compact list summaries, observations and overrides. Size the whole atomic request for simultaneous field edits. Test a long background and goal through detail, typed save, receipt replay and archive import. If long overrides are permitted without a seed, choose the archive version by the values it must represent. [World limits](../../packages/contracts/src/world-library.ts#L42) · [Cast limits and receipt](../../packages/contracts/src/campaign-cast.ts#L36)

4. **First-appearance eligibility can change after copy or recovery.** Line 233 introduces a per-campaign eligibility marker. Lines 203–210 and 264–276 describe copying events, but an eligible campaign can have zero events, just like a legacy campaign. Make eligibility explicit portable campaign metadata. Define defaults for older archives, imports and new campaigns created with presets off. Preserve it on branch, migration, transfer and both archive types. Round-trip an eligible empty campaign and an ineligible legacy campaign, then present the same first appearance to each. [Cast copy](../../packages/database/src/campaign-cast-lifecycle.ts#L38) · [Transfer insert](../../packages/database/src/campaign-transfer-character-repository.ts#L408) · [System Archive import](../../packages/database/src/system-archive-import-repository.ts#L811)

5. **A renamed protagonist can be copied as an NPC.** Lines 172 and 237 exclude the main character at creation and Add from world. The first-appearance and held-approval rules at lines 221–232 match any eligible Supporting or Both entry. Once a Both protagonist is renamed in the campaign, the old roster name can match the world identity while missing the current cast name. Reserve the scoped selected roster ID on every seeding path, including review approval, and guard manual Apply targets on the server. Test an appearance under the former name with both matching policies. [Name and world matching](../../packages/domain/src/campaign-cast-discovery.ts#L187)

6. **Queued discovery has conflicting rules after migration or flag shutdown.** Lines 221, 232 and 251 combine a frozen job policy, the campaign's current pinned version and a promise that disabling presets stops seeding. Publication currently reconciles against the captured version, while the write rejects an origin from a different pin. Define a commit-time rule under the campaign lock. Re-resolve the same roster identity against the current pin and send changed or ambiguous cases to review. For shutdown, either veto new seeds at commit or explicitly require operators to drain admitted jobs before rollback. Test a job paused before publication across each change. [Publication](../../packages/database/src/campaign-cast-discovery-publication.ts#L49) · [Write guard](../../packages/database/src/campaign-cast-repository.ts#L265)

7. **The prescribed provider projection permits text the cast already rejects.** Lines 177, 257, 355 and 732 preserve raw authored text, then specify mechanics stripping and truncation for narrator context. That pipeline alone leaves credential-like strings and some cast-specific mechanics or private-reasoning forms. Reuse the allowlisted character-fiction projection, apply the cast fiction checks to the outgoing values, and omit unsafe fields before building narrator content, discovery hints or Draft from story input. Keep the full original on the campaign sheet. Verify the actual provider-bound payload with synthetic credential, mechanics, reasoning and extension-field fixtures. [Character-fiction projection](../../packages/domain/src/character-fiction-authority.ts#L33) · [Cast fiction checks](../../packages/domain/src/campaign-cast.ts#L13)

8. **Prompt compatibility is a required decision before phase 3.** Lines 355–366 change field names, authority, source IDs, notices and selection behavior. Line 1107 leaves the protocol bump open. ADR 0023 explicitly requires a protocol change when character context changes shape. Preserving an old snapshot hash does not preserve the prompt rendered from it. Version the new context and prompt together, rebuild incompatible response chains, and dispatch already-admitted jobs through their frozen protocol. Verify both old-job retry output and the first new request. [ADR 0023](../architecture/0023-structured-character-profiles.md#L26) · [Frozen protocol validation](../../packages/contracts/src/story-memory-policy.ts#L212)

9. **The context budget cannot guarantee core fields for every selected character.** Lines 363–365 and criterion 3.23 promise all selected characters core coverage. Thirty pins with 600-character fields can exhaust the 3,000-token ceiling during the first pass alone. Available headroom can also be zero. Define a minimum representation, reserve space for identities first, then allocate fields in rounds and report omissions deterministically when the minima cannot fit. Test zero headroom and many long profiles under a tight budget, including the promised recency ranking. [Budget and selector](../../packages/domain/src/campaign-cast-context.ts#L12)

## Editor, API and existing clients

10. **Campaign Organize can fail on Save.** Line 429 carries `editSource`, but the persistence layer rejects `ai_organized` without `organizerProtocolVersion`. Nexus currently omits it. Preserve the reviewed proposal's protocol version in staged draft state, through conflict/reapply and into the typed save. Verify the actual campaign Organize → review → Save path, including the recorded provenance. [Nexus save](../../apps/web/src/nexus.js#L4242) · [Repository guard](../../packages/database/src/campaign-transfer-character-repository.ts#L145)

11. **The Apply world profile preview lacks its data contract.** Line 245 promises the exact values that will become fixed and the overrides that will be cleared. Line 578 gives the client only use, defaults, role and a short summary. The route inventory at lines 508–520 supplies no read for the full pinned NPC or its resolved target. Add a campaign-scoped preview returning eligible target, exact field changes and relevant revisions, or extend a typed read to provide equivalent data. Revalidate the preview on write. Test same-name candidates and a target edited while the preview is open. [Existing character summary](../../packages/contracts/src/client-api.ts#L166)

12. **Web-Next can overwrite the world settings Nexus adds.** Lines 466 and 1083 preserve new flags during Nexus generation while deferring Web-Next. Its current generator spreads generated fields over the existing candidate, so parsed defaults can replace Supporting or Both with Playable. Its review validation also requires a structured story field on a legal name-only NPC. Protect use, defaults, identity and hidden mechanics at the shared write boundary, or limit incompatible Web-Next writes until adoption. Test a Nexus-authored NPC through ordinary and durable Web-Next generation. [Generation merge](../../apps/web-next/src/character-workspace-model.ts#L226) · [Review validation](../../apps/web-next/src/character-workspace-model.ts#L264)

13. **Two promised Story controls lack server support.** Line 611 and criterion 2.4 ask for the actual source of each main-character field as a UI-only change. The read exposes profile-level inheritance, and a fresh campaign already has a stored world copy. Use an accurate profile-level label in phase 2 or add per-field provenance from the edit history. Separately, lines 336, 347 and 612 keep the existing review queue while forbidding the override it offers for blank seeded stable fields. Return permitted actions per item and route an explicit stable-field edit through the authored save, or offer dismissal alone. Test a seeded protagonist with one edited field and a pending detail on a blank seeded NPC field. [Profile response](../../packages/contracts/src/client-api.ts#L115) · [Campaign creation](../../packages/database/src/world-repository.ts#L1192) · [Shared review queue](../../apps/web/src/cast-review-queue.ts#L139)

14. **The proposed campaign-create error is lost on the wire.** Lines 176 and 512 expect HTTP 503 with `cast_presets_disabled`. The world adapter produces an ordinary error, and the global handler redacts generic 5xx details. Explicitly expose this one safe error and add the new readiness issue to the adapter's issue allowlist. Assert the actual HTTP envelope and typed-client behavior for a disabled instance and a Supporting-only roster. [World error mapper](../../services/api/src/world-campaign-application-adapter.ts#L93) · [HTTP exposure rules](../../services/api/src/server.ts#L572)

15. **The story import path still permits a Supporting protagonist.** Lines 155 and 1109 leave additional roster readers to audit. The Infinite Worlds story-text preview offers the full pinned roster, auto-selects from its length and accepts any matching ID. Use the selectable resolver for import preview and revalidation at apply. Test a world with one Playable and several Supporting characters, plus a submitted Supporting ID. Existing campaigns can retain a historical main-character selection. [Story import preview](../../services/runtime/src/portable-import-export-composition.ts#L1553)

## Automation and the separately released lifecycle work

16. **A valid citation can still be a claim about the wrong person.** Lines 732–742 exclude claim observations but admit paragraphs containing mentions. A paragraph can mention the NPC and include another person's description or a quoted allegation. Checking that the evidence ID exists would let either become a fixed authored field. Give factual proposals subject-attributed, fact-eligible spans, verify the proposed value against its cited span, and retain the explicit creative-guidance exception. Test dialogue, a second subject, negation and a narration correction between preview and save. [Discovery's existing attribution and claim checks](../../packages/domain/src/campaign-cast-discovery.ts#L207)

17. **Suggest a cast has incompatible count and input-budget rules.** Line 669 drops duplicates and permits fewer results. Criterion 5.1 requires three to eight, even if every suggestion collides. Specify zero through the requested count plus an empty-state action, or budget a bounded refill. Lines 668–671 also add entity names to a bounded prompt in a world that can contain 20,000 entities. Cap provider-bound names while checking collisions against the complete roster and entity set on the server. Test all-duplicate output and a large world. [World collection limits](../../packages/contracts/src/world-library.ts#L138)

18. **Renaming a converted entity can split alias ownership.** Lines 695 and 710–714 allow a converted roster character to take a different name. Discovery skips the linked entity, while Chronicle retains its identity through the link. An original name can consequently become unique to a different person in one system and ambiguous in the other. Define which original names survive or are retired, and share that rule across the two catalogs. Test a rename caused by a collision before and after the character has a campaign copy. [Discovery identities](../../packages/domain/src/campaign-cast-world-identities.ts#L27) · [Chronicle entity references](../../packages/domain/src/entity-references.ts#L169)

19. **Merge cannot express all reviewed choices or preserve hand authority predictably.** Line 789 asks the user to trim the merged alias list to 20, but line 762 accepts only source/target choices per field. Lines 803–807 also leave conflicting manual overrides unresolved and say the latest observation wins for updating fields, even when a hand override exists. Add the reviewed aliases to the request, validate them against the normalized union, and specify precedence for manual values, empty overrides and observations. Store the choices needed for undo. Test conflicting hand-edited goals, alias trimming and a subsequent target edit. [Identity command](../../packages/contracts/src/campaign-cast.ts#L75) · [Override precedence](../../packages/domain/src/campaign-cast.ts#L67)

20. **Promotion can offer two writes to one field or produce a nameless entry.** Lines 855, 862 and 871 copy authored appearance directly and map observed appearance into `appearance.otherVisualDetails`. Both can be ticked with different values. Add also requires a valid world name while the preview describes every field as optional. Build the preview by destination path, require a valid name on Add, and resolve the two appearance values before the write. Verify Replace changes only the approved destinations. [World profile and required name](../../packages/contracts/src/world-library.ts#L78)

21. **Phase 6 introduces a separate rollback boundary.** Lines 203–217 describe cast archive v3 and a first-seed boundary. Lines 757 and 918 separately release merge and remove, gated by cast editing. A deployment that has never enabled presets can still write a lifecycle event that an earlier strict reader cannot parse. Install compatible live and portable readers before enabling those writes. Either deliver all readers earlier or introduce a separately gated lifecycle format, such as v4, and document the first lifecycle write alongside the first Supporting world, settings save and seed. Verify rollback and imports with a lifecycle-only campaign. [Strict commands](../../packages/contracts/src/campaign-cast.ts#L67) · [Archive version validation](../../packages/contracts/src/campaign-cast.ts#L127)

## Smaller specification and acceptance corrections

- **Define what Remove does to pending reviews.** Lines 832–838 hide removed characters from attention counts and allow later discovery to attach silently. A candidate already awaiting review is read independently of those counts and can still offer a write. Filter both identity proposals and resolved-detail receipts by the current removal state in the inbox and resolution route. Specify whether still-valid pending items return on Restore. Test a candidate created before Remove and a discovery job completing afterward. [Pending candidate query](../../packages/database/src/campaign-cast-candidate-repository.ts#L24)
- **Specify what happens to authored edits after a mistaken match.** Lines 189 and 227 suppress the seed but address authored edits only by cast character ID. If a character is later seeded again, projection needs to know which edits belong to the former seed. Associate edits with a seed event or define equivalent replay rules. Test a hand edit between first appearance and detach, followed by reapplication of the same profile and application of a different eligible profile.
- **Preserve legacy guidance in mixed records.** Line 144 specifies a fallback only when `profile` is absent, but a world character can contain distinct authored `characterText` and a structured profile at once. Line 450 hides the legacy text for presets. To meet goal 3, retain it separately as read-only origin guidance or specify and disclose the exclusion. Test with different values in both fields. [World character contract](../../packages/contracts/src/world-library.ts#L87)
- **Correct the System Archive field list.** Line 153 can be read as adding the same fields to roster entries and generic entities. Roster profiles already round-trip. Specify roster use/defaults for phase 3 and entity `linkedCharacterId` for phase 5. The exporter drops roster `source` today. Classify conversion/promotion provenance and permit only the intended typed shapes if they must round-trip. [World exporter](../../packages/database/src/system-archive-export-repository.ts#L364) · [Portability ADR](../architecture/0037-exhaustive-portability-classification.md)
- **Make the flags table usable when conditions overlap.** Lines 380–388 describe independent conditions as rows. Discovery can be off while a campaign is unenrolled or needs a higher Story Memory capability than the instance provides. Specify notice precedence using the campaign's effective status and separate the successful create result from the editable form so actions cannot resubmit it. Test these combinations on Create and Create and start. [Per-campaign capability comparison](../../packages/database/src/campaign-cast-repository.ts#L582)
- **Repair the acceptance checklist.** Criteria 1.2/1.3 and 6.9/6.10 run together at lines 925 and 1029. Give each its own list entry. Add the cases above to the relevant phase, distinguish replay and archive fixtures from browser checks, and require the repository's screenshots for changed visible interactions.

This was a static design and source review. The proposed behavior has no executable implementation to test in this change.
