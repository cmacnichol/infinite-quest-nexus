# Character review dismissal and retraction acceptance

## Stage A and Stage B: verification evidence; final review pending

Stage A covers source-scoped pending identity and detail dismissal, separate decisions, and Undo. Skip remains temporary. A dismissal does not remove a turn or accepted fact and is not a global ban on a name. A corrected narration or evidence from another turn can return to review. Journal dismissals are excluded from branches and archives; older pre-journal dismissals remain effective but cannot be listed or undone. Character removal remains governed by the existing lifecycle capability, and the interface explains when it is disabled. Stage B adds accepted-fact retraction and restoration; the evidence and limits below cover both stages.

The composed proof caught a continuity defect: creating a character after dismissing a detail could allow a rescan that supplied the new character ID to publish that detail. The reviewed fix binds the retained source and proposal to a unique resolved identity, retains distinct-person isolation, and falls back conservatively when bindings are ambiguous. PostgreSQL tests cover create and attach, automatic world seeding, distinct people sharing a quotation, ambiguous persisted identity bindings, changed sources and stale Undo. No schema or prompt change was needed for this fix.

### History scaling limit

The [scoped Dismissed reader](../../packages/database/src/campaign-cast-review-decision-repository.ts) loads active decisions, legacy dismissals and resolved bindings, then checks each active decision's candidate and source before slicing a page; eligible selected entries can require another resolved-candidate query. A source-level model for 100 valid active decisions and a 25-item first page gives up to 228 queries (3 bulk reads + 200 candidate/source reads + 25 resolution reads), plus revision, snapshot and transaction queries; eligibility short-circuit can reduce this.

An isolated local PostgreSQL fixture with 100 active identity dismissals from one synthetic source returned 25 entries in each of three sequential reads. Instrumenting the client counted **237 queries per read**, including transaction, snapshot and revision work; elapsed times were **192.7, 189.1 and 180.8 ms**. These measurements characterize this fixture and local setup, not production latency or a performance threshold. History matching also scans scoped bindings and active/legacy entries in application memory. Profile representative installations and consider batching; no production performance change was made in this gate.
