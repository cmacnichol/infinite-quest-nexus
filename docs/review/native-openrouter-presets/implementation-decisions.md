# Native OpenRouter preset implementation decisions

**Story routing correction (2026-09-23):** For newly queued Story work, the selected preset remains the wire target (`model: "@preset/<slug>"`) alongside the operation's strict `json_schema`. OpenRouter owns model/provider routing and fallback; the application sends no `provider` routing block and does not retry concrete preset candidates. This supersedes the concrete-candidate dispatch decision below for new Story jobs only. Historical snapshots and other text workflows retain their existing behavior. See the [correction record](story-preset-schema-correction.md).

The consolidated F1–F9 review established two further binding boundaries. First, an operationless generic text request cannot claim Preset trust or a Required Model's verified operation/schema; it must fail before dispatch. Second, physical-attempt accounting is separate from output acceptance. The durable attempt ledger stores each observed charge once, including partial usage after terminal 2xx rejection; an owner-scoped logical/job projection serves direct and authoring work without inventing campaign ownership. Applicable Story/illustration campaign cost reads include those ledger charges and deduplicate a matching successful cost event by stable call identity. Missing usage and currency distinctions remain explicit. These rules are covered by unit and real-PostgreSQL tests indexed in [verification](verification.md).

This record captures final product and operational decisions. Earlier choices about agent models, task splitting, and review process were implementation logistics and are not product authority.

| Decision | Rationale and cost if wrong | Final evidence |
| --- | --- | --- |
| New direct Model selections use Required Structured Outputs; native Presets use trusted schema admission. | Models need exact advertised and current operation/schema/stream/route verification. Presets retain every configured route without a local capability filter. Conflating the two would either admit an unverified Model or incorrectly remove a preset route. | `packages/application/src/providers/response-format.ts`; `services/runtime/src/generation-response-contract.ts`; model/preset admission and operation-matrix tests |
| Every active text operation carries its own complete v2 schema. | Reusing the Story schema for authoring, events, coverage, organizer, source, or illustration refinement would violate the consumer contract. A missing operation must block rather than silently weaken format. | `packages/contracts/src/provider-output-schema.ts`; `tests/unit/generation-response-contract-operation-matrix.test.ts`; offline 17-operation probe artifact |
| The preset prompt is composed exactly once before the earliest body measurement. | Planned, measured, stored, and dispatched bytes must be identical. Double insertion corrupts budget and behavior; late insertion bypasses preflight. | prepared execution/body capture tests across Story, direct/durable/source authoring, organizer, and illustration refinement |
| Frozen route/schema closure and per-invocation prompt plans are separate identities. | Multiple invocations can share a schema and frozen route basis while using distinct operation prompts. Collapsing them loses replay integrity or causes false cross-call matches. | `packages/contracts/src/generation-response-contract.ts`; `packages/database/src/generation-execution-repository.ts`; response-contract persistence and reclaim tests |
| Saved ordinary settings are frozen, while current credential, endpoint, owner, and enabled authority still gate dispatch. | A queued job must not adopt later selection edits, but revoked execution authority must still stop it. Refreshing remote preset metadata during reclaim would reinterpret durable work. | queue/reclaim authority tests in generation, authoring, and illustration suites |
| Candidate and provider order are explicit inputs. Route advance is bounded to pre-output availability failures. | Public catalog order is not private preset priority. Schema/refusal/auth/cancel/ambiguous failures and any failure after output are terminal. Getting this wrong can send a different model or duplicate partially observed work. | `packages/story-engine/src/preset-route-execution.ts`; executor route/failure units and PostgreSQL workflow tests |
| Physical attempts sit beneath one logical invocation. | Reserved/dispatched/output/completed state, usage, and observed serving identity must survive fallback and crashes without double charging or blind resend. | migration 0100, generation execution repository, preset workflow and two-job isolation tests |
| Downlevel workers are fenced by transaction-local protocol capability and immutable native markers. | A historical worker must not claim or reinterpret native Story, authoring, or illustration work as an alias. The cost is mixed-version starvation, so all workers must be upgraded before admission is enabled. | migration 0098 and exact historical claim/reclaim SQL tests |
| `turn_intent` remains retired. | Intent profile data remains compatible for setup and persistence, but reviving runtime generation would add an unplanned consumer and contract. | active-operation catalog and provider consumer inventory tests |
| Completed preset summaries may be cached; in-flight discovery is not shared. | Each caller keeps independent cancellation. The cost is bounded duplicate metadata requests during overlap, limited by request bounds and the 60-second completed cache. | OpenRouter preset discovery transport and cancellation tests |
| Direct multi-operation workflows keep one stable request scope with distinct logical invocation identities. | Grouping outline and seed operations under one scope preserves request ownership while pair identities prevent reservation collisions. | direct prepared execution and concurrent-template workflow tests |
| Legacy browser eligibility uses one browser-safe current Story identity checked against the canonical catalog. | The browser bundle cannot depend on Node-only schema code. A consistency test prevents a stale digest from admitting or blocking a Model after a schema change. | `packages/client-core/src/providers/story-response-format-capability.ts`; provider-selection editor consistency tests |
| Native admission stays production-default-off. | Capturing a v2 snapshot without every executor and worker fence available is unsafe. API advertisement and each enqueue boundary follow the same gate. | runtime configuration, API capability projection, and flag-off/on boundary tests |
| Images and embeddings never inherit text preset prompts, routing, or credentials. | Nontext provider lifecycles are independent. Explicit invalid preset embedding configuration fails rather than borrowing the text route. | image/embedding independence and import/archive PostgreSQL tests |
| Portable preset selections remain unresolved until destination metadata validation succeeds. | An archive cannot prove that another account owns the same preset version or routing. First-candidate substitution would silently change authority. | provider/archive contract and PostgreSQL round-trip tests |

Operational verification uses a task-owned PostgreSQL service with the repository's normal isolated-per-file database setup. This prevents changes to shared or production databases while retaining the same migrations and pgvector image. It is test-environment evidence, not a product behavior decision.
