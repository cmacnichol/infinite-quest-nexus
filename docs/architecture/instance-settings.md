# Installation settings authority

Protected deployments start in environment mode until an operator activates a reviewed database revision. A local single-user installation seeds and activates its first revision at startup. The singleton is installation-scoped. The immutable revision registry holds 43 scalar settings across Characters and authoring, Sharing and archives, Performance and requests, and Diagnostics. The installed application resolves the active revision once per startup after migrations and before it constructs the API, worker scheduler or provider services. A browser Save appends a requested revision using compare-and-swap and records the actor and changed field names. Running processes continue serving their original snapshot.

Policy files define the installation UUID, implementation protocol, role pools and replica limits, feature gates, reviewed numeric intervals, and approved rate-count/window combinations. External gates can restrict a stored preference. A numeric value outside the approved range or a divergent active policy fails validation. Database bootstrap credentials, keys, storage, address and network allowlists, pool size, rollout gates, maintenance authority and the archive ceiling exception remain deployment decisions. The base replicated Swarm layout always disables System Archive.

A maintenance transition advances the activation epoch under a database advisory lock. Fresh reports include process, role, build, protocol, revision, epoch, effective digest and readiness. Registration and serving have separate barriers. A role needs its steady count of eligible processes, and all fresh reports including stopping members must fit its explicitly approved maximum. All fresh reports must agree on compatibility. Stopping members can occupy surge capacity and cannot satisfy readiness. Image identity and absence of older uninstrumented binaries require external operator verification.

User Profile stays in the user menu in both clients and owns all personal and device controls. Its server-resolved UUID also scopes device storage. Provider profiles, prompts, and world or campaign preferences retain their existing authority, save behavior, and separate credentials. Protected management requires an operator key, exact-origin HTTPS, a short-lived session cookie, and a CSRF token for writes. Direct loopback HTTP installations can explicitly opt into local single-user management. In that mode, the initial owner can stage changes from the local browser, and each revision and audit event records local-owner authority. Subsequent activation uses the same drain and policy checks in both modes.

System Archives exclude revisions, state, management sessions, key fingerprints, unlock attempts, reports, local admission history, and policy/secret files. A restore target may already have installation management authority. Existing portable content, conflicting owner authority, share/asset grants, and incompatible active work retain their existing restore protections.
